# Changelog

## 0.2.0 (unreleased)

**Language detection, and the dash rule stands down outside English.** The language of each file is declared (`--language`, or `"language"` in `.slop.json`), read from a `lang:` key in the front matter, or detected from the prose for French, Spanish, German, Italian, Portuguese and Dutch. For text that is not English the `dash` rule does not run, and the output names the language it used. Inside an English file, a paragraph of at least 12 tokens written in another language has its English-only findings dropped. A dialogue line that opens a paragraph with a dash, and a dash inside `« »`, `‹ ›` or `„ “` quotations, are exempt in any file. A short quoted line of fewer than 12 tokens in an English paragraph is not exempt. [docs/LANGUAGES.md](docs/LANGUAGES.md) states the limit and the measured rates.

**`--compare` reports the facts a rewrite lost or added.** `slop --compare before.md after.md` (also `slop diff`) lists each number, version, date, link, quotation, code span and name that appears in one text and not the other, and exits 1 when there is one. `--json` gives the three lists. It compares facts, not wording, so it cannot say whether a rewrite is good. The agent skill runs it after every rewrite.

**A rule for invisible characters.** `invisible-character` (warning, house rule) reports zero-width spaces and joiners, the word joiner, a byte order mark inside the text, direction marks and controls, invisible operators and Unicode tag characters in Latin-script prose; the message names each code point. Joined emoji, subdivision flags, text in a script other than Latin (Thai, Persian, Indic), a byte order mark at the start of the file and direction marks on a line with right-to-left text are left alone, and the soft hyphen is not reported. `--fix` deletes a run that touches a space, punctuation or a line end; a run between two letters is reported without a fix, because deleting it would join two words. On the precision corpus it fires on neither side (`bench/PRECISION.md`); across the 97,872 words of human text in `bench/corpus`, `bench/packs/human` and `bench/typography` it fires 146 times, all in three Spanish Wikipedia files that carry real zero-width spaces left where citation markers were removed. The idea comes from everwrite's `tells.py` (MIT); the code is ours.

**`--compare` reads a qualifier next to a number as part of the fact.** A rewrite that keeps `3` but drops `up to`, or turns `300` into `over 300`, prints `lost qualifier up to 3` or `added qualifier over 300` and exits 1. The words cover English, French, German and Spanish (`at least`, `nearly`, `environ`, `jusqu'à`, `bis zu`, `mehr als`, `hasta`, `más de` and others), grouped by meaning so that a swap within a group is silent. A number that changed is reported as a number only. `about` after a verb such as `talked`, `over` and `über` before a span of time, and Spanish `hasta` before a year are read as their other sense. Each qualifier was kept only if it flagged none of the 24 goldens, none of the 357 round 1 rewrites by the base model and the competitors, and none of 40 hand-written honest pairs; English `about` and `approximately` were dropped. The table is `bench/COMPARE-QUALIFIERS.md`, generated by `node bench/compare-qualifiers.mjs`. The MCP tool `compare_facts` returns the new kind too.

**A French rule pack, one rule, provisional.** `fr/closer` flags a call to act followed by `dès aujourd'hui`. It has no hit on 40,160 human words, and four hits in four files on 4,373 words of machine text from three invented products. The pattern was chosen after seeing those hits and has not been tested on new text. Spanish and German ship no rule: no candidate passed the shipping limit, and the tool does not claim to detect model text in either language. The candidates, their counts and their verdicts are in [bench/packs/CANDIDATES.md](bench/packs/CANDIDATES.md).

**The agent skill fires on rewrites in any language, and it has a CI setup recipe.** Its description now covers rewrite requests, requests written in other languages, launch and release notes, and asks to set up a CI prose check; the skill gives a `lint:prose` script that lints a glob, not a file list.

**The agent skill edits less and checks its own draft.** "How to work" now asks for the smallest edit: a sentence without a tell is copied word for word. A text over about 300 words is outlined first, so a repeated point or the same closer under each section is fixed before single words. After the draft, a second pass lists every tell still there, quoting the line, and fixes or justifies each; the list goes in the reply, not the file. The steps are adapted from unslop, Humanizer and everwrite (MIT, see `THIRD-PARTY-NOTICES.md`). The CI setup recipe moved to `skills/ai-slop-linter/references/ci.md`, and `SKILL.md` keeps a short pointer to it.

**The agent skill was rewritten for other languages.** It defines the temporary directory for the before copy explicitly, states exactly what the dash rule does for text in another language, and adds a section of stock French, Spanish and German phrases to look for by reading. The CLI does not enforce that section.

**The Claude Code plugin has a `UserPromptSubmit` hook.** In round 1 of the head-to-head, two of three h2 runs never loaded the skill: the agent read the file, edited it and ran no check. `hooks/hooks.json` now runs `hooks/rewrite-prompt.sh` (POSIX `sh`, `sed`, `tr` and `grep`; no network, no file writes) on every prompt. When the prompt asks to rewrite, clean up, polish, proofread, humanize or tighten prose, in English or with verbs such as réécris, reformule, reescribe, schreib um, überarbeite, yeniden yaz or düzelt, it adds one line of context telling the agent to use the skill, lint first and treat a failing `--compare` as blocking. A verb that also applies to code (rewrite, fix, clean up) counts only next to a prose noun such as paragraph, email, README or a `.md` file. It prints nothing on other prompts, never blocks one and exits 0 on malformed input. `test/prompt-hook.test.mjs` runs it on 78 related and 79 unrelated prompts (all caught, none flagged), but those are in-sample: three later batches measured before the patterns were tuned on them caught 23 of 47 related prompts and flagged 4 of 47 unrelated ones. The benchmark's `ours` plugin export and code manifest now include `hooks/`. The line also carries the skill's guardrails, so they hold when the agent never opens the skill: add no `we`, `our`, `I`, claim or fact the source lacks, keep every number with its qualifier, read `references/<lang>.md` for French, German or Spanish, and run `--compare` until it exits 0.

**A star hint, and `--quiet`.** After a clean run in an interactive terminal the CLI prints one line asking for a GitHub star, once per machine. It stays silent for `--format` other than text, `--fix`, `--commit`, `--pr`, `--explain`, `--history`, standard input, CI, a git hook and a recognised AI agent. `--quiet` (`-q`) or `AI_SLOP_LINTER_NO_STAR_HINT=1` turns it off, and neither changes the exit code or any other output.

**`--compare` reads first-person words and claim words.** A rewrite that turns "In benchmarks" into "In our benchmarks" kept every fact and still named an owner the source never did. `--compare` now reports `person` facts (a first-person word that the rewrite has more of, or fewer of, than the source: `our`, `we`, `ich`, `nous`, `nuestro`, `biz`) and `claim` facts (a claim word such as `always`, `guaranteed` or `because` that the rewrite has more of; removing one is never reported). It exits 1 on either, and `--json` and the MCP `compare_facts` tool carry the new kinds; `compare_facts` takes an optional `language`, since detection cannot tell a text under about 25 words or a Turkish one. Text in double quotation marks, code, urls, link targets and words joined into a name (`us-east-1`, `my-app`, `docs/our-guide.md`) are not read. Only words that passed a measurement are flagged: each one flagged no golden rewrite and at most 5 percent of the honest rewrites of the round 1 head-to-head, and `bench/COMPARE-WORDS.md` lists every candidate with its verdict (`node bench/compare-words.mjs --check` runs in CI). The agent skill treats such a line as blocking.

**Reference files for tells a regular expression cannot catch.** The agent skill now makes the agent read `skills/ai-slop-linter/references/<language>.md` after the linter, on every rewrite: an English catalog adapted from everwrite's pattern catalog, a German list adapted from unslop's German lists, and French and Spanish lists of stock renderings of English tells. Each entry gives the tell, why it reads as machine prose and the fix direction, under the rule "add no fact, change no number". The CLI does not enforce them. The skill also says that a failing `--compare` blocks the rewrite until it exits 0. Each file now has two tiers, "Act on one sighting" and "Act only when several appear", so a strong tell is fixed at once and an ordinary word is left alone unless it comes in a cluster. All four files name the load-bearing metaphor (`pays off`, `zahlt sich aus`, `porte ses fruits`, `da sus frutos`, and nouns such as `backbone` or `pilier`) with its literal uses protected; the French, German and Spanish files name the trailing participle or gerund clause that grades the sentence before it. The Spanish file grew from a short list to the full set of families. The second tier of the French, German and Spanish files adds words that Juzek (2026, data CC0) measured as overused by a language model in news text; they count only several together and are not linter rules.

**MCP `compare_facts`.** The MCP server has a fourth tool, `compare_facts`, which takes a `before` and an `after` text and returns the facts the rewrite lost or added, as `--compare` does. Read-only and deterministic.

**Pack rules appear wherever rules are listed.** The SARIF `rules` list and every result's `ruleIndex` include the language pack rules (`fr/closer`), `--rules` lists them in their own section, and the MCP `explain_rule`, `only` and `ignore` accept their ids. Before, a SARIF result for `fr/closer` had no `ruleIndex`, and `explain_rule` answered that the rule did not exist.

**Dash precision fixes.** A dialogue-opening dash is judged on the raw line, so a line that starts with inline code and then a spaced hyphen is no longer taken for one. An English paragraph that opens with a dash is no longer exempt; the exemption now needs a paragraph that is plausibly not English (another language detected from five words, a Spanish raya, or too few English function words to read as English). A short English paragraph is no longer called foreign on one repeated word such as "over" or "plus": paragraph mode needs three distinct function words and three hits. A `lang = "fr"` key in TOML front matter is read like the YAML one. Matching findings to paragraphs is a binary search, so a file with tens of thousands of paragraphs lints in about two seconds instead of several times that.

**Four fixes from the readiness check of the new benchmark tasks.** The built CLI and the committed fixtures and goldens were run against tasks h13 to h18 before any model run. `--compare` no longer reads the first word of a table cell as a name, so a table whose cells open with a tell word ("Delves", "Pivotal") no longer reports lost names against its clean rewrite. `--compare` leaves names out of German and Luxembourgish text, where every noun is capitalised and the h17 golden reported 18 lost nouns; the language is `--language`, the front matter or detection. `curly-quotes` no longer flags, and `--fix` no longer straightens, the closing mark of a German low quotation. `title-case-heading` stands down outside English, because German headings of nouns read as Title Case. The CI recipe in the agent skill now lints `"**/*.md"` instead of `"docs/**/*.md"`, which let a bad README pass, and it says how to handle a CHANGELOG and a README that quotes a stock phrase.

**A head-to-head harness.** `bench/head-to-head/` holds the fixtures and scripted checks for twelve tasks, and [docs/HEAD-TO-HEAD.md](docs/HEAD-TO-HEAD.md) states the tasks, the criteria and the rule for a win. A first round with five tasks found two of them saturated (every arm scored full marks), and they were replaced. Results are published there once the comparison has been run on the final build.

**`slop --mcp` serves the linter to AI agents.** An agent can now call `check_slop` on text, `check_slop_file` on a path and `explain_rule` for one rule over the Model Context Protocol on standard input and output. Each finding comes back as JSON with line, column, severity and, for a safe fix, the exact character range and replacement. A rule id the agent misspells is an error result, not a clean one. The server is a separate module that the command loads only for `--mcp`, so the package still has no dependencies. `docs/mcp.md` has the setup commands for Claude Code and Codex. Those two clients were not run against it; the tests speak the protocol directly.

**A textlint rule.** `ai-slop-linter/textlint` runs the same rules as the command line inside textlint, reports each finding at its position and offers the safe fixes to `textlint --fix`. It is tested against a stand-in for textlint's context. That stand-in cannot show that textlint runs `--fix` only for a rule with a `fixer` export, so the `textlint` job in `ci.yml` is meant to run it against real textlint 15.8.0: `scripts/textlint-smoke.mjs` installs the packed package and textlint into an empty directory, then checks lint output and that `textlint --fix` removes a dash. The job is defined in `ci.yml` and has not yet run on a remote runner; it was run locally. The package that textlint users install is `textlint-rule-ai-slop`, in the `textlint-rule-ai-slop/` directory; it is not yet published.

**A VS Code extension, built to a `.vsix`.** The `vscode/` directory holds an extension that underlines findings in Markdown, plain text and commit message editors while you type, offers the safe fixes in the quick fix menu and contributes the problem matcher `$ai-slop-linter`. The `vscode` job in `ci.yml` is meant to pack it, install the file into a real VS Code under a virtual display and check that diagnostics and a quick fix work. The job is defined in `ci.yml` and has not yet run on a remote runner; it was run locally. It is not on the Marketplace, because publishing needs a publisher account.

**Commit message rules, measured on commits people wrote.** `--commit`, `--commit-msg`, `--pr` and the commitlint rule also run rules only a commit message gets: framing such as "as part of this change", hedges such as "this should fix", marketing words, trailing justifications and unquantified speed claims. The phrase lists are adapted from [tbhb/vale-ai-tells](https://github.com/tbhb/vale-ai-tells) by Tony Burns (MIT), and the notice stays in `src/commit-phrases.ts`. Each rule was run on commit messages from Django and Flask written before 2021. `bench/COMMIT-RULES.md` shows which candidate rules measurement ruled out and which phrases it dropped. A README or any other file never sees these rules.

**A new first screen.** `README.md` opens with the problem in a user's words, one sentence that says what the tool is, `npx ai-slop-linter README.md` and a recording of the tool's real output (`docs/demo.gif`, made by `docs/demo.tape` from the build in this repository). The sections on scoring, other languages, measurement, our own writing, SARIF and citation moved to `docs/` with a stub and a link left in the README. The stars badge is gone and the remaining badges link to their pages. A table lists every surface, with the MCP server, the textlint rule and the VS Code extension marked as not yet released. `docs/PAIN.md` lists the public reports behind the opening sentence. `README.tr.md` has the same first screen.

**One description everywhere, and files for search and for language models.** The npm description, the README's first paragraph, `llms.txt`, `llms-full.txt` and the playground's meta description carry the same sentence, and `test/category.test.mjs` fails when one differs. The package gains search keywords. `docs/FAQ.md` answers the common questions, `docs/GEO-PROMPTS.md` fixes five prompts for measuring whether language models name the tool, and `docs/LISTINGS.md` holds the text for each store; `action.yml`, the plugin manifests and the extension and textlint package descriptions match it. `llms-full.txt` is generated by `scripts/llms-full.mjs` and checked by a test. The playground page gains a description, social tags, `SoftwareSourceCode` JSON-LD and a sitemap.

**Corrections.** `llms.txt` said twenty rules and sixteen more; there are twenty-one prose rules and five commit-message rules, and `test/counts.test.mjs` now derives the counts from the code. `README.tr.md` said twenty rules and four READMEs; it now says twenty-one and five. The README's `--history` sample printed a personal e-mail address and now shows a run on this repository for the public noreply address. The claim about 56 agent directories is gone because it could not be checked. The own-writing table was run again on the current version and is dated in `docs/OWN-WRITING.md`.

**The README's own lint was partly switched off.** The linter reads a `slop-ignore` comment on any line, including one shown as an example in a code block. The README's examples named `dash`, `emoji`, `vague-source` and `triad`, so those rules did not run on the rest of the file. The examples now use a placeholder, and `test/ignore-directives.test.mjs` fails when a shipped document names a real rule in an ignore comment, or when a dash added at the end of the README is not found.

## 0.1.10 (2026-10-14)

**`--format markdown` keeps a backslash before a pipe inside its cell.** The table escaped `|` but copied
`\` through, so a path or message containing `a\|b` came out as `a\\|b`: an escaped backslash followed by a
bare pipe, which ended the cell early and shifted every column after it. Backslashes are now escaped too. A
test lints a file named `a\|b.md` and splits each row the way GitHub's table parser does. On the 53
Markdown and text files in this repository the markdown and JSON output is byte-identical before and after,
because none of them produces a backslash.

**The Action can be listed on GitHub Marketplace.** Marketplace refused `action.yml` because the description was 148
characters, where it accepts fewer than 125. It is now 123. A test now fails on a description of 125 characters or more.
Nothing a workflow uses changes.

## 0.1.8 (2026-10-14)

**SARIF artifact paths now remain valid URI references.** Paths are normalized from backslashes to
forward slashes and each segment is percent-encoded, so spaces and non-ASCII names survive schema
validation. The `$schema` field now uses the OASIS SARIF 2.1.0 errata01 schema URL. The schema test
invokes the CLI on real filenames with spaces and non-ASCII characters and validates each emitted
log. Written by [@Aaqibhafeezkhan](https://github.com/Aaqibhafeezkhan) (fix for
[#45](https://github.com/Bubblegunn/ai-slop-linter/issues/45)). Two parts that a run on macOS or
Linux cannot reach are tested since the merge: a Windows path (`docs\my notes\café.md` becomes
`docs/my%20notes/caf%C3%A9.md`) and the `$schema` value; removing the backslash step or restoring
the old URL fails that test. The README's SARIF example no longer runs `sarif-multitool validate`,
the step [#43](https://github.com/Bubblegunn/ai-slop-linter/issues/43) showed could not fail, and
the README now credits the SARIF output, the pre-commit hooks and `reference-markup` to their author
where each is described.

**A rule for the markup chatbots leave behind when their answers are copied.** `reference-markup`
(`error`) reports internal citation and rendering tokens such as `:contentReference[oaicite:0]{index=0}`,
`oai_citation`, `turn0search0`, `grok_card` and `[attached_file:1]`, which the guideline's "Reference
markup bugs" subsection documents and no earlier rule covered. It is an error rather than a warning
because the tokens are machine residue, not a matter of style. Each of the seventeen alternatives
is listed in the guideline, and each has its own test line, so deleting any one of them fails the
suite. Tokens inside code, URLs and fenced blocks are masked and stay silent, so a document that
explains the bug does not trip it. Written by [@Aaqibhafeezkhan](https://github.com/Aaqibhafeezkhan)
([#46](https://github.com/Bubblegunn/ai-slop-linter/pull/46), closes
[#14](https://github.com/Bubblegunn/ai-slop-linter/issues/14)), who also did the wiring that is easy
to forget: the package allowlist, the hosted playground's engine and the rule counts in the
documentation. Measured on the human corpus it fires zero times, which is what `bench/PRECISION.md`
now records.

**The SARIF check in CI could not fail.** `sarif-multitool validate` exited 0 on every broken file it
was given: a missing required property, a missing `version`, a file that is not JSON, a result
`level` of `fatal` and a `columnKind` of `bytes`. It printed the first three as errors and then
`Analysis completed successfully.`; it did not report the last two at all. The step is replaced by a
test that validates the CLI's SARIF against the vendored OASIS 2.1.0 schema with ajv, formats
included, and a test for each of five defects that the check must reject. Both directions were
broken on purpose to watch them fail (#43). Nothing in the published package changes.

**Two quadratic paths, found by a new run-time test.** `test/perf.test.ts` runs every rule over
fourteen generated worst-case inputs of about 100,000 characters each (long runs of `-`, `—`,
`–`, `,`, `**`, spaces and tabs, an unclosed fence, one line with no newline) and fails any rule
that takes more than a second on one of them. Each rule runs in a worker that is terminated
when it overruns, so a pattern that never returns fails the test instead of hanging it; a rule
rewritten to `(a+)+$` was used to check that. On the first run it found two real faults. `dash`
retried its leading whitespace from every position of a run of spaces, so a file of 100,000
spaces took 4.5 s. And the excerpt every finding carries, with the line-start check in the dash
fix, re-read the whole line once per finding, so 100,000 en dashes on one line took 3 to 5 s.
Both are now linear: the slowest rule on any of the inputs takes 40 ms on the same laptop. On Node 20 and 22 the
`dash` rule stayed slow until its list-marker lookbehind was moved out of the pattern, which V8
before Node 24 re-scanned from every position of a run of spaces; CI on those versions caught it. The
findings and fixes are unchanged, compared on every Markdown file in the repository and on
30,000 generated strings.

**Coverage is measured in CI.** A `coverage` job runs the suite under Node's built-in coverage and
fails when lines, branches or functions in `dist/src` fall below 98.96 %, 89.86 % and 98.83 %,
the values measured on 2026-10-14 on macOS and in a Linux container (they agreed). The script
checks the thresholds from the lcov totals itself: Node 24 reads its own `--test-coverage-lines`
as a whole number, so 98.9 was enforced as 98 and a run with a test deleted passed it. With
that test deleted, the new check fails at 98.84 % lines and 89.24 % branches. `npm run coverage`
runs the same thing locally. Nothing in the published package changes.

**The release workflow checks what Action and pre-commit users receive.** After a publish, the
smoke job installs the release into an empty project and requires `npm audit signatures` to
report a verified provenance attestation, not only a registry signature, because the command
passes a package that has no attestation at all. On Linux it then checks with `git ls-remote`
that `v0` points at the same commit as the new `vX.Y.Z`, and that the `vX.Y.Z-pre-commit` tag's
tree contains `dist/src/cli.js`. Both tags are moved by `npm run release` from the maintainer's
machine, after the tag that starts the workflow, so the checks retry the way the install check
does. Each was run against the real 0.1.7 tags (pass) and against wrong ones: `v0.1.6`, where
`v0` is elsewhere; `v0.1.5`, which has no pre-commit tag; and a tree without the build (all
failed). `left-pad@1.3.0`, which has a signature and no provenance, failed the first check.

**The Action's metadata file did not parse, and a failing run lost its findings and its
comment.** Two faults in `action.yml`, both in every release since 0.1.0, found by running the
Action in CI for the first time. The `comment` input's description was an unquoted YAML value
containing `pull-requests: write`, and a colon followed by a space ends an unquoted value: PyYAML
and Ruby's Psych both reject the file at line 17, column 131. It is quoted now, and a test fails
on any unquoted value with `: ` or ` #` in it. Second, GitHub runs a composite step's bash with
`-e`, so when the lint found an error-severity tell and returned 1, the step ended on that line:
the `findings` output was never written and the review comment was never posted or updated, on
exactly the pull requests that needed them. The exit code is now captured and returned at the
end.

**`files` accepts a path with a space.** The input was split on spaces, so `docs/my notes.md`
became two paths that do not exist, and the CLI skips a missing path without a word when another
one matches. One path or glob per line (`files: |`) now keeps spaces, and on either form a path
that does not exist fails the run with a message that says how to pass it. A one-line value
without such a path behaves as before. A new `package` input runs a local package in place of the
published `version`; it exists so the new `action` CI job can run `uses: ./` against the package
built from the same commit, and checks the `findings` output against the CLI's own count, that
`warn-only: "false"` fails on the sloppy fixture, that the clean fixture reports 0, and both
forms of a path with a space. `test/action.test.mjs` runs the Action's script the way GitHub
runs it, with `-eo pipefail`. Each check was run against a broken copy of `action.yml` (the old
splitting, a count off by one, `exit 0`, the old exit handling, the unquoted description) and
failed.

## 0.1.7 (2026-09-22)

**The release gate died on npm 12 and forbade the entry you are reading.** `npm pack --dry-run
--json` returns an array on npm 11 and an object keyed by package name on npm 12, and the gate read
`packed[0].files`. And its CHANGELOG check required the top entry to carry the package's current
version, while `release.mjs` refuses to release until an entry for the new version exists, so a
contributor's credit could only ever be written at release time.

**SARIF output, so findings survive the pull request they were found in.** `--format sarif` emits
SARIF 2.1.0 for GitHub code scanning, with every rule in the run metadata carrying its description
and the source it cites, severities mapped straight across (`error`, `warning`, `info` to `error`,
`warning`, `note`) rather than promoted, and `columnKind: utf16CodeUnits` declared beside columns
this tool already reports in UTF-16 code units. Written by
[@Aaqibhafeezkhan](https://github.com/Aaqibhafeezkhan) ([#41](https://github.com/Bubblegunn/ai-slop-linter/pull/41),
closes [#10](https://github.com/Bubblegunn/ai-slop-linter/issues/10)), whose test puts a surrogate
pair before the finding so the asserted column, 4 in UTF-16 units and 3 in code points, pins the
declaration to the value. The generated file is validated in continuous integration rather than
eyeballed.

Both fixes are [@shivam-070208](https://github.com/shivam-070208)'s, written on workproof
([#35](https://github.com/Bubblegunn/workproof/pull/35) and
[#29](https://github.com/Bubblegunn/workproof/pull/29)) and ported here with his four tests. Each
port was checked by re-running the mutation that ignores the requested package name, which fails
exactly its own test. Nothing in the published package changes; this is the tooling that decides
whether a release may happen at all.

## 0.1.6 (2026-09-20)

**No rule changed. A checkout of this repository could not run, and nothing here could tell.**
`bin` pointed at `dist/src/cli.js`, `dist/` is gitignored, and nothing built it at install time, so
`npm i github:Bubblegunn/ai-slop-linter` installed a package with no `node_modules/.bin` entry at
all. The tarball on the registry was always correct, which is exactly why twelve green checks said
nothing: every check on a pull request builds first and then tests the build directory, so none of
them saw what a stranger receives.

One check did, and it is worth naming rather than claiming none existed: the release workflow's
`smoke` job installs the published package from the registry on three operating systems. It covers
the npm route, it runs only after publishing, and it asserts `--version` rather than that the linter
lints. It could not have caught this, because the route that broke is the git checkout.

Found by [@Aaqibhafeezkhan](https://github.com/Aaqibhafeezkhan), who tried to use the repository
rather than read it: his pre-commit hooks ([#27](https://github.com/Bubblegunn/ai-slop-linter/pull/27))
were correct and reported `Executable not found`, because `pre-commit` installs a hook repository
from a git checkout.

**`npm run release` now also tags `vX.Y.Z-pre-commit`**, at a commit whose tree is the release plus
the paths `files` declares. Pin that rev in `.pre-commit-config.yaml`; the ordinary release tag and
`main` stay free of build output. The commit is assembled through a temporary index and
`git commit-tree`, so releasing touches neither the working tree nor the real index
([#30](https://github.com/Bubblegunn/ai-slop-linter/pull/30)).

A `prepare` script was the obvious answer and it is not one. Measured: it works under npm 11.6.2 and
fails inside `pre-commit`'s own Node environment with `TS2688`, and npm 12 removes the road rather
than narrowing it. Its defaults are `allow-git = "none"` and lifecycle scripts off, so a git
dependency is refused outright and an install-time build would not run even if it were fetched.

**The check that would have caught it now exists**: `npm pack`, a real install of that tarball into
an empty directory, every `bin` name asserted present, and the executable run on an eighty-one word
file written to fail. Eighty-one, because this linter does not grade anything under fifty: a
shorter file would pass against an empty binary and prove nothing
([#33](https://github.com/Bubblegunn/ai-slop-linter/pull/33)).

**The release gate no longer forbids the entry the release script requires.** It demanded the top
`## ` heading equal `package.json`'s version on every push, so no entry could be written between two
releases and an outside contributor's credit could only ever appear at release time. It recognises
two states now and says which one it found. Ported from workproof, where
[@shivam-070208](https://github.com/shivam-070208) fixed the same contradiction, together with the
shared version comparator that stops the two scripts disagreeing again, and with the nine tests this
repository's gate had never had ([#32](https://github.com/Bubblegunn/ai-slop-linter/pull/32)).

**The playground keeps the rules you switched off.** Turning a rule off in the browser now produces
the `.slop.json` the command line, the hook and the Action all read, so a decision made there holds
where the work happens. The page also prints the two kinds of choice a config cannot carry, findings
dismissed one at a time and the commit-message reading, rather than silently dropping them
([#28](https://github.com/Bubblegunn/ai-slop-linter/pull/28)).

## 0.1.4 (2026-09-05)

Before this went out, every rule was run against correct published typography in thirteen languages, one text per language, all public domain and all typeset before any language model existed. The table is `bench/TYPOGRAPHY.md`, the corpus and its licences are in `bench/typography`, and the argument is `docs/typography-across-languages.md`.

One rule failed badly. `dash` carries the highest severity here and fires 73.5 times per 1,000 words on correct Polish, 52.1 on Hungarian, 24.0 on Russian, and 22.0 on French once that file's em dashes are restored from the two hyphens its transcriber typed (0 as it stands; `bench/TYPOGRAPHY.md` prints both columns), against 1.0 on the English human baseline. The Polish, Hungarian and Russian files grade F for punctuating their own language correctly: the em dash is ordinary in French, opens dialogue in Spanish, and in Russian stands where the verb would go. So a repository can now declare what it writes in, `"language": "fr"` in `.slop.json` or `--language fr`, and `dash` stands down, with the run saying which rules did not run so a quiet result is never read as a clean one. English is the default, so no existing repository sees a change. This is configuration rather than detection on purpose: a README with English headings over French prose defeats a guess in both directions. A density threshold was measured first and does not work, because correct German prose sits at 6.7 findings per 1,000 words and the machine corpus in `bench/PRECISION.md` sits at 5.7.

`curly-quotes` now judges each quote family against the straight form of its own family. Chinese uses the curly double marks as its primary quotation marks and nests straight apostrophes inside them, which is correct Chinese; the rule read that as a paste artifact and reported 21.7 findings per 1,000 words on the Chinese text, now zero, with the English corpus unmoved. The cost is that a file whose only straight mark is an apostrophe no longer has its curly double quotes reported.

`hyphen-density` counted `[a-z]+-[a-z]+`, so `peut-être` and every other compound carrying a non-ASCII letter was invisible and the rule quietly did nothing outside English. It counts Unicode letters now. Measured after the change across both corpora: the highest rate in any file is 1.4 per 100 words against a threshold of 3, so nothing new fires.

`dash` also counted the Chinese 破折号, which is written as two em dashes, as two findings. A run of em dashes is one mark.


`Intl.Segmenter` existing is not the same as ICU carrying the word dictionaries it needs. A Node built with small ICU constructs the segmenter and then hands back a whole run of Japanese, Chinese, Thai, Khmer, Lao, Burmese or Tibetan as a single segment, which is the "a three-thousand-character document counts as one word" bug again, this time with no symptom: the document would grade F whatever it said. The segmenter's answer is now checked per run instead of trusted, and a run of twelve characters or more that comes back as one word falls to the two-characters-per-word estimate. Per run, so a build carrying the dictionary for one of these scripts and not another gets the right treatment for each. Nothing changes on a full-ICU build, which is what CI and the published binaries use.

Every release is archived on Zenodo and `CITATION.cff` now carries the concept DOI
`10.5281/zenodo.22396875`, so a finding rate quoted in a paper can name the rule set that produced it.
That matters more here than in most tools, since this release changes what three rules do.

Both READMEs gain a section on where a finding points: the column is a 1-based UTF-16 offset in logical order, which is what editors, GitHub annotations and language servers use, and for a reader of Arabic or Hebrew that is not the position the eye sees. The finding's `excerpt` is the part meant for reading; the column is for the tool that jumps to it.

## 0.1.3 (2026-09-05)

`bench/agents.mjs` measures whether machine-written commit messages carry the tells this linter looks for, using the declaration the messages make themselves: an agent trailer, an agent suffix in the author name, or a known agent address. Trailers are stripped before counting, because the trailer is the label. Two runs are written up in `RESEARCH.md`, and the second is the reason it exists: on langchain-ai/openwiki the `dash` rule, the only one reported as an error, fires about two and a half times less on the declared side. One repository is an anecdote, and what it establishes is that the direction is not obvious.

The score's design has a citation and its conventions are admitted. Charoenwet, Thongtanunam, Pham and Treude (ISSTA 2024) found warning density the most effective prioritisation and warning severity the least, which is the shape this tool's per-1,000-words score takes; the README also says the study ranks warnings per line of code in security review rather than findings per words of prose, so it supports the shape and proves nothing about this tool. The severity weights and the grade boundaries are labelled as conventions with nothing behind them.

A test now fails when a test file exists and is not named in the test script, after that mistake hid tests twice in one day in two repositories.

A `.mailmap`, because `surviving-lines --identities` reported this repository as two people.

`CITATION.cff` carries keywords and the author's ORCID, which are the fields an archive reads when it mints a record.

## 0.1.2 (2026-09-05)

`--history` reads your own commit messages back over time: weighted tells per 1,000 words per month, quarter or year, with the most common rule in each period. It defaults to the address in the repository's own git config, so the thing it shows you first is your own writing. Trailers are not counted, because a `Co-Authored-By` line is a template rather than prose. There is no grade and no exit code: a bar comparing one period against another describes writing over time, and a lone period gets no bar at all, because a bar is a comparison. `--author`, `--by month|quarter|year` and `--since` narrow it; `--format json` gives the periods for charting.

## 0.1.1 (2026-09-05)

Words are counted in every script. The counter matched `[A-Za-z0-9'’]+`, so a run of
Japanese was a single token and a word containing a non-ASCII letter split into pieces.

| document | characters | words before | grade before | words after | grade after |
|---|---:|---:|:--:|---:|:--:|
| Japanese | 626 | 1 | F | 323 | C |
| Japanese, longer | 3,334 | 1 | F | 1,691 | A |
| Chinese | 460 | 1 | F | 232 | C |

| Turkish | 1,334 | 264 | C | 136 | D |

Length now counts for something: the longer Japanese document grades A where the shorter
one grades C, and both were F before at any length. Turkish moves the other way, because
its words were being split at every non-ASCII letter, which inflated the count and
flattered the score. Scripts that separate words are tokenised; Chinese, Japanese, Thai
and the rest go through the platform's Unicode segmenter rather than a
characters-per-word constant nobody measured.

`--languages`, and `"languages"` in `.slop.json`, switch on a rule pack for a language
other than English. No pack ships: the registry is empty, English is unchanged and always
on, and asking for a language with no pack is an error rather than a quiet clean run.
`checkLanguagePack` states what a pack has to satisfy, an id prefixed by its language and a
source on every rule, and CONTRIBUTING.md records which languages can be sourced from the
same authority the English rules use. Issue #1 tracks the first pack, and the rules in it
are an outside contributor's to write.

A directory argument lints the Markdown inside it, which is what running with no target
does for the whole repository. It used to print `EISDIR: illegal operation on a directory,
read`. A directory holding no Markdown now says so and exits 2.

A document under 50 words is no longer graded. Below the floor one finding decides the
letter, so a twelve-word fragment with one em dash printed a confident F. The findings
still stand and an error still fails the run; only the letter is withheld. Commit messages
and pull request descriptions keep their score, since they are short by nature and the
question there is whether the text carries a tell. `bench/scripts` adds one paragraph of
the same release notes in seven scripts, each with one em dash, and `bench/PRECISION.md`
records what each scores, so the counting cannot regress unnoticed.

The English corpus moved by five words in 5,929, from two words carrying accents that
were previously counted as four. No grade changed; `pep-8-style-guide.md` moves from 3.2
to 3.3.

## 0.1.0 (2026-09-05)


A nested Markdown list no longer reads as a spaced hyphen. Indentation followed by a hyphen is a bullet, so a README with nested items took three errors and an F; the rule now refuses a hyphen preceded only by indentation, and the measured corpus is unchanged.

A fenced block now closes on a file with CRLF line endings. The closing marker was matched with `[ \t]*$`, which a trailing carriage return fails, so on Windows a fence stayed open and masked the rest of the document. Caught by the Windows leg of CI on the fixture above, and pinned by a test that feeds the same fixture with CRLF endings.

Masking covers four constructs it missed. Code quoted by four-space or tab indentation, which is how a README shows a diff, was linted as prose, so a diff line beginning `-  ` was reported as a spaced-hyphen dash. A fenced block inside a blockquote was not recognised as a fence. The contents of HTML `pre` and `code` blocks were visible to the rules. Front matter was matched only in its YAML form, so a TOML header was linted. Content indented under a list item stays visible on purpose, because list continuation is prose more often than it is code. Fixture: `test/fixtures/quoted-code.md`.

<!-- slop-ignore-next-line filler -->
`filler` no longer matches "in order to" when a determiner follows it. "Overrides are applied in order to any file" is "in order" plus "to", not the padded infinitive; the tool found this on its own README.

`.slop.json` takes `overrides`: a list of `{ files, ignore, only, maxScore }` entries applied in order to any path that matches, so published docs can be held to a stricter score than a changelog. `--only` runs the named rules and nothing else, `--skip` is another spelling of `--ignore`, and both reject an unknown rule id instead of doing nothing.

`--init` writes a `.slop.json`, `--init action` the pull request workflow and `--init hook` the commit-msg hook. It refuses to overwrite a file that exists, and it names every file it wrote.

`--explain <rule>` prints one rule in full: why the pattern reads as machine-made, a line that trips it, the same line rewritten, and the case where a maintainer should switch it off. Every rule carries the material, and a test asserts that each rule's own example trips it. The text output names the command for the first rule that fired, on stderr so the machine-readable format is untouched.

A measured corpus in `bench/`: five public-domain texts written before any language model (Austen, Douglass, Darwin, PEP 8, PEP 257) and five pieces of unedited model output. `npm run bench` writes `bench/PRECISION.md` with the rate per rule in each corpus and lists every finding on the human side; CI fails when the committed table is stale. The human texts grade A or B, the model texts F.

`curly-quotes` no longer fires on a document that uses curly marks throughout. It flagged all 92 lines of dialogue in an excerpt of *Pride and Prejudice* and nothing in the model corpus, because consistent curly marks are typography. It now reports only a file that mixes curly and straight marks, which is what pasting from a chat interface leaves.

`not-x-but-y` catches the contracted forms (`isn't just X, it's Y`), which are the common ones, and recognises `that's`, `they're` and `it was` as the second half.

First release.

- Twenty rules, each with a named source (mostly Wikipedia's "Signs of AI writing"), three severities, line and column numbers
- Masking for front matter, fenced and inline code, link targets, URLs, HTML tags and comments, so a dash in code is never a finding
- `--fix` for dashes, curly quotes and filler phrases; fixes are idempotent and never change meaning
- Score per 1,000 words and an A to F grade, with `--max-score` and `.slop.json`
- `--commit`, `--commit-msg <file>` and `--pr <n>` for the text that actually goes into a repository
- `--format github` annotations, a composite GitHub Action, a commit-msg hook and an installer
- A Claude Code skill and plugin manifest; also installable with `npx skills add Bubblegunn/ai-slop-linter`
- The Action lints the pull request title with the body, posts one review comment with the findings table and updates it on every push (`comment`, `baseline` inputs, `findings` output); `--format github` marks each failing text with an error line; `--format markdown` prints that table for issues and reviews
- A commitlint plugin and shareable config (`ai-slop-linter/commitlint`, `ai-slop-linter/commitlint/config`) with one rule, `ai-slop-linter/tells`
- A VS Code task with a problem matcher for the text output (`.vscode/tasks.json`), and a test that pins the line format (#2)
- `--baseline` and `--baseline-write`: record the findings a repository already has and fail only on new ones, keyed by file, rule and sentence rather than line number (#3)
- A moving `v0` tag: every release moves it to the released commit, so `uses: Bubblegunn/ai-slop-linter@v0` follows the newest release in that major without editing the workflow The release workflow starts on full version tags only, so the moving tag cannot start a second publish.
