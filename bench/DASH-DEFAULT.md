# Should `dash` fail the build by default?

Generated by `node bench/dash.mjs`. Do not edit by hand; CI fails when this file does not match a fresh run. No default has been changed. This is the evidence for a decision that belongs to the maintainer.

## The question

`dash` has severity `error`, so one em dash in a file fails the run (exit 1) whatever the rest of the file looks like. The topic is contested: readers argue that people have always used the em dash. This file measures what each alternative would do on the committed corpus (`bench/corpus`), nothing more.

## Files that fail, by policy

A file fails when it has an error-severity finding or its score is above the limit. Limit 10 is the default; 3 is what this repository sets in `.slop.json`.

| policy | human, limit 10 | machine, limit 10 | human, limit 3 | machine, limit 3 |
|---|---|---|---|---|
| dash is an error (today) | 4 of 5 | 5 of 5 | 4 of 5 | 5 of 5 |
| dash is a warning | 0 of 5 | 5 of 5 | 0 of 5 | 5 of 5 |
| dash is off | 0 of 5 | 5 of 5 | 0 of 5 | 5 of 5 |

Human files are texts written before 2021. Machine files are unedited model output. Lower is better for the first and third columns; higher is better for the second and fourth, if failing on model output is what you want.

Under today's policy these human files fail at the default limit:

- `human/darwin-origin-of-species.md`
- `human/douglass-narrative.md`
- `human/pep-257-docstrings.md`
- `human/pep-8-style-guide.md`

## What this does not show

- 5 human files and 5 model files. Some of the human files are more than a century and a half old, and none is a modern README.
- It does not measure how readers react. Whether a failing build over one dash costs more goodwill than it saves is a judgement about people, not a number here.
- It does not say a file was written by a model. It counts a character.

## Decision needed

Pick one, and the change is one line in `src/rules/dashes.ts` plus the tests that name the severity:

1. Keep `error`. Put the one-line reason and the off switch (`--ignore dash`) on the first screen of the README.
2. Make it `warning`. A dash then counts one towards the score and fails a file only when the score is above the limit.
3. Keep `error` but only from a density (the table above), which needs a new threshold option.
4. Turn it off by default. The rule stays available with `--only dash`.
